# PokemonGame 기획 결정 체크리스트

이 문서는 [레퍼런스 조사](01_레퍼런스_조사.md)를 바탕으로 결정할 사항을 정리한 것입니다. **옛날 원작 드래곤빌리지를 참고하고 포켓몬과 결합한다는 방향, 이번에는 기획을 구체화한다는 작업 범위는 확인되었습니다.** 그 밖의 규칙·수량·검증 기준은 제안 또는 미정입니다. [구체적인 플레이 초안](03_게임_구조와_첫_플레이.md)과 [검증 순서](04_검증_범위와_의존성.md)를 비교하며 결정합니다.

다음 결정 순서는 **① 포켓몬에서 가져올 재미 ② 플랫폼·제작 기간·인원 ③ 알 또는 포획 ④ 전투 방식 ⑤ 육성 선택과 탐험의 연결**입니다. 이미 답한 원작/컬렉션 질문을 다시 할 필요는 없습니다. 포켓몬에서 상성만 참고하면서 자동 전투를 택하는 조합도 가능합니다. 특정 엔진·턴제·속성 수·파티 크기는 아직 확정하지 않습니다.

## 2 한 문장 콘셉트 작성란

> 플레이어는 [역할]이 되어 [장소]에서 [획득 행동]으로 독자 생물을 얻고, [육성 선택]을 통해 [차별화된 능력]을 만든 뒤, [탐험 또는 전투 목표]에 도전한다.

이 작성란의 구체적인 후보는 [게임 구조 초안의 두 결합안](03_게임_구조와_첫_플레이.md)에 있습니다. 후보를 검토한 뒤 선택한 내용을 기록합니다. 추가로 채울 세 문장:

- 가장 자주 하는 재미있는 선택: 미정.
- 이 게임에서만 기대하게 만들고 싶은 경험: 미정.
- 첫 버전에서 우선순위를 낮출 요소와 그 이유: 미정.

## 3 우선순위 1 핵심 규칙을 연결하기

### 획득과 수집

- [ ] 원하는 생물의 위치·조건을 어떻게 알아내는가? 서식지 단서, 도감 힌트, 임무 중 무엇을 쓸까?
- [ ] 획득은 확정 보상인가, 확률인가? 확률이라면 실패 이유와 재시도 비용을 이해할 수 있는가?
- [ ] 첫 동료와 첫 번째 새 동료는 어떤 순서로 얻는가?
- [ ] 알이라면 부화 조건은 플레이 행동·재료·현실 시간 중 무엇인가? 기다리는 동안 할 일은 무엇인가?
- [ ] 같은 종류를 다시 얻을 이유는 무엇인가? 없더라도 수집이 지속되는가?
- [ ] 보관 한도와 정리 방법은 무엇인가? 원치 않는 획득 때문에 플레이가 막히지 않는가?

### 육성과 애착

- [ ] 성장이 능력치만 늘리는가, 기술·역할·탐험 능력도 바꾸는가?
- [ ] 성장 조건과 예상 결과를 미리 보여줄 것인가?
- [ ] 무작위 개체 차이를 넣는다면, 좋아하는 동료를 버리지 않고 개선할 방법이 있는가?
- [ ] 잘못 고른 성장·기술을 바꿀 수 있는가? 바꿀 수 없다면 언제 충분히 설명하는가?
- [ ] 외형 단계가 늘 때마다 필요한 그림·애니메이션을 감당할 수 있는가?
- [ ] 닉네임·행동 반응·짧은 동료 기록 중 어떤 요소로 애착을 표현할까?

### 전투와 편성

- [ ] 전투의 승리 조건과 패배 비용은 무엇인가? 패배 후 무엇을 바꾸고 재도전할 수 있는가?
- [ ] 보유 수, 데리고 다니는 수, 동시에 전투하는 수를 각각 정했는가?
- [ ] 기술·교체·방어·도구 중 실제로 필요한 행동은 무엇인가?
- [ ] 행동 순서, 기술 비용, 사용 횟수 또는 재사용 시간은 어떻게 설명하는가?
- [ ] 상성·역할·상태 효과 가운데 첫 전투에서 가르칠 규칙은 무엇인가?
- [ ] 한 가지 최강 선택으로 끝나지 않도록 다른 해결법이 있는가?
- [ ] 무작위 결과를 허용한다면 판단과 운의 비중을 어떻게 보여주는가?
- [ ] 자동 전투라면 준비의 효과와 패배 원인을 알 수 있는가? 실시간이라면 거리·범위·예고를 읽을 수 있는가?

### 탐험과 진행

- [ ] 탐험 중 실제 선택은 이동 경로·위험 감수·자원 사용·관찰 중 무엇인가?
- [ ] 길 찾기, 생물 발견, 전투가 어떻게 한 세션 안에서 이어지는가?
- [ ] 지역 해금 조건은 이야기·조사 성과·성장 능력·승리 중 무엇인가?
- [ ] 새 동료나 성장한 동료로 이전 지역에 다시 갈 이유가 있는가?
- [ ] 보스를 쓰러뜨리는 것 외에 수집·조사 목표가 필요한가?
- [ ] 1회 플레이 길이와 전체 목표는 어느 정도인가? 중간에 그만두기 쉬운 지점이 있는가?

### 재화와 저장

- [ ] 필요한 재화마다 획득처와 사용처가 있는가? 용도가 같은 재화를 중복해서 만들지 않았는가?
- [ ] 핵심 성장에 필요한 자원을 계속 얻을 수 있는가?
- [ ] 획득·부화·성장·보상 수령 중 어느 시점에 저장하는가?
- [ ] 종료 후 재개할 때 동료와 진행 상태가 어디까지 유지되어야 하는가?
- [ ] 온라인 기능이나 수익화가 정말 첫 검증에 필요한가? 필요하다면 담당 범위와 운영 부담을 별도 정의했는가?

## 4 작은 검증 범위 제안

다음은 완성 게임의 규모가 아닌 **처음 재미를 확인할 한 사이클의 예시**입니다. 제작 조건을 확인한 뒤 줄이거나 바꿀 수 있습니다.

| 요소 | 예시 범위 | 확인하려는 점 |
| --- | --- | --- |
| 공간 | 작은 거점 1곳과 탐험 지역 1곳 | 다음 행동을 스스로 찾을 수 있는가? |
| 생물 | 역할이 다른 독자 생물 3종, 성장 전후 2형태 이내 | 각 동료를 선택할 이유와 성장의 차이가 보이는가? |
| 획득 | 주력 방법 1개 | 획득 과정 자체가 재미있는가? |
| 육성 | 의미 있는 선택 1번 | 선택의 결과를 다음 도전에서 체감하는가? |
| 전투 또는 도전 | 일반 상황 1종과 마무리 도전 1개 | 같은 규칙으로 다른 판단을 유도할 수 있는가? |
| 보상 | 다음 획득이나 성장으로 이어지는 보상 | 한 번 더 플레이할 목표가 생기는가? |
| 저장 | 한 슬롯의 저장·이어하기 | 얻고 기른 동료가 유지되는가? |

파티 크기, 속성 수, 기술 수, 수치 공식은 위 표에서 결정하지 않았습니다. 처음부터 온라인 PvP·거래·교배·대규모 마을 꾸미기·방대한 도감·여러 성장 체계를 함께 만드는 것은 보류할 후보입니다. 보류 여부는 최우선 재미와 제작 조건에 따라 정합니다.

자산 규모도 먼저 셉니다. 예를 들어 **3종 × 2형태 × 3상태 = 18개 상태 표현 세트**입니다. 네 방향 표현이 각각 필요하면 72세트가 됩니다. 이것은 산식 예시이며, 정지 그림인지 여러 프레임 애니메이션인지에 따라 실제 제작량은 달라집니다. 종 수만으로 아트 규모를 판단하지 않습니다.

### 구현 전에 종이나 문서로 확인할 순서

1. 획득 → 육성 선택 → 도전 → 보상의 흐름을 한 장에 그립니다.
2. 동료 3종의 역할과 선택지를 카드처럼 적고 한 번의 도전을 수동으로 진행합니다.
3. 서로 다른 육성 선택이 다른 해결법을 만드는지 확인합니다.
4. 차이가 없다면 종류를 늘리기 전에 선택과 보상의 연결을 고칩니다.
5. 사용자와 핵심 규칙을 정한 뒤 구현 범위를 확정합니다.

### 검증 질문과 판단 기록

- [ ] 설명을 듣지 않은 사람이 다음 목표와 획득 방법을 말할 수 있는가?
- [ ] 성장 선택 후 무엇이 달라졌는지 플레이어가 설명할 수 있는가?
- [ ] 어려운 상황에서 다른 동료·기술·준비를 선택할 이유가 있는가?
- [ ] 실패 후 바꿔볼 행동을 스스로 떠올리는가?
- [ ] 마무리 보상으로 다음 탐험을 하고 싶어지는가?

각 질문의 결과를 **관찰한 행동 / 막힌 이유 / 바꿀 규칙 / 다시 확인할 항목**으로 기록합니다. 좋아요 여부만으로 판단하지 않습니다. 필요한 참가자 수와 수치 목표는 제작 목적을 정한 뒤 설정합니다.
