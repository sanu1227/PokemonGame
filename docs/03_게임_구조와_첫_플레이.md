# PokemonGame 게임 구조와 첫 플레이 초안

갱신일: 2026년 11월 4일. 이 문서는 [레퍼런스 조사](01_레퍼런스_조사.md)를 구체적인 선택지와 플레이 흐름으로 바꾼 **기획 제안**입니다. 원작을 복제하는 명세나 확정된 개발 사양이 아닙니다.

## 1 확정 사항과 아직 선택할 사항

| 구분 | 현재 상태 |
| --- | --- |
| 사용자 확인 | 예전 원작 드래곤빌리지와 포켓몬을 참고한다. 드래곤빌리지 컬렉션은 대상이 아니다. |
| 이번 작업 | 프로젝트 안에서 조사와 기획을 더 구체화한다. 구현을 시작한 상태는 아니다. |
| 참고 범위 미정 | 원작의 정확한 연도·패치, 포켓몬에서 원하는 작품과 재미. |
| 제작 조건 미정 | 플랫폼, 2D·3D, 엔진, 제작 인원, 사용 가능한 자산, 마감·투입 시간. |
| 설계 미정 | 알·포획의 비중, 성장·전투 방식, 파티 크기, 탐험 구조, 공개 범위. |
| 이 문서의 숫자 | 비교와 수동 진행을 가능하게 하는 예시다. 제작량·일정·최종 밸런스 약속이 아니다. |

원작의 현재 스토어 설명은 알 발견·부화·육성·대결이라는 큰 흐름을 확인하는 데 사용했습니다. 2024·2026년 공지는 별도 후대 자료이며 사용자가 기억하는 옛 버전과 같다고 가정하지 않습니다. 포켓몬도 작품별 차이가 있어 아래 커맨드 전투는 여러 참고 방식 중 하나입니다.

## 2 서로 다른 두 결합안

### A안: 알을 찾아 기른 동료로 길을 여는 게임

> 탐사 육성가가 서식지의 단서를 따라 알을 발견하고, 부화한 동료의 성장 역할을 고른 뒤, 그 역할에 맞는 준비와 행동으로 다음 탐험의 도전을 해결한다.

- **살릴 재미:** 원작 드래곤빌리지의 알 발견과 육성 기대감에, 포켓몬에서 참고할 수 있는 상성·기술·편성 판단을 연결한다.
- **주력 행동:** 목적지 단서 읽기 → 알 획득 → 성장 방향 선택 → 역할에 맞게 도전하기.
- **첫 검증에서 확인할 것:** 같은 동료라도 키운 방향 때문에 다음 행동이 달라지는가?
- **장점:** 새 생물을 얻는 순간과 애착을 쌓는 시간이 연결된다. 한 지역과 소수 동료로도 전체 흐름을 보여줄 수 있다.
- **손해·위험:** 부화와 육성이 단순 대기·반복 수집이면 발견의 보상이 늦어진다. 무작위 능력치가 지배하면 개체를 버리는 플레이로 흐를 수 있다.
- **검토할 대응:** 첫 부화는 목표 행동으로 완료하고, 성장 결과를 미리 보여준다. 무작위 개체 차이와 재육성 비용은 별도 비교한다.

### B안: 서식지를 관찰하고 동료를 확보하는 모험 게임

> 생태 조사원이 야생 생물의 행동을 관찰해 접근 방식을 고르고, 확보한 동료의 특징으로 탐험 경로와 도전 해결법을 넓힌다.

- **살릴 재미:** 포켓몬에서 참고할 수 있는 야생 탐색·포획·도감 목표에, 원작 드래곤빌리지의 한 개체를 기르는 만족을 결합한다.
- **주력 행동:** 서식 단서 찾기 → 접근·획득 판단 → 동료 성장 → 새로운 조사 목표.
- **첫 검증에서 확인할 것:** 생물을 찾고 접근 방식을 고르는 과정 자체가 재미있는가?
- **장점:** 획득 전부터 플레이어의 발견과 판단이 있다. 지역의 생태·탐험을 게임의 차별점으로 만들기 좋다.
- **손해·위험:** 이동·시야·야생 행동·실패 후 재등장까지 필요해진다. 실시간 포획이면 조작과 애니메이션 부담도 커진다.
- **검토할 대응:** 처음에는 작은 연결 구역과 소수 행동 패턴으로 제한한다. 알은 처음부터 완전한 두 번째 획득 체계로 넣지 않고 필요성을 먼저 확인한다.

| 선택 기준 | A안이 더 맞는 경우 | B안이 더 맞는 경우 |
| --- | --- | --- |
| 가장 기다려지는 순간 | 어떤 동료가 부화하고 어떻게 자랄지 | 어디에 무엇이 살고 어떻게 얻을지 |
| 포켓몬에서 원하는 부분 | 상성·기술 선택·동료 구성 | 야생 탐색·포획·도감 완성 |
| 우선 필요한 표현 | 알·개체·성장 선택·도전 결과 | 이동·단서·야생 행동·접근 결과 |
| 먼저 줄일 요소 | 부화 대기·중복 성장 체계 | 넓은 맵·복잡한 야생 행동 |

**어느 안도 채택하지 않았습니다.** 둘 다 원한다면 획득·육성·전투를 한꺼번에 확장하기보다, 먼저 확인할 재미를 정하고 주력 획득 방식 하나로 첫 구간을 완성하는 안을 제안합니다. 알 중심에 자동 전투를 붙이거나 포획 중심에 커맨드 전투를 붙이는 조합도 가능합니다.

## 3 공통 게임 순환과 단계별 책임

**다음 목표 선택 → 서식지 탐험 → 동료 획득 → 성장·편성 → 도전 → 결과·보상 → 다음 목표 선택**

| 단계 | 플레이어가 볼 정보와 할 선택 | 남는 결과 | 다음 단계로 이어지는 이유 |
| --- | --- | --- | --- |
| 목표 | 얻을 동료·필요한 자원·도전 조건 중 목표 선택 | 현재 목표와 목적지 | 무엇을 찾는지 알고 출발 |
| 탐험 | 단서와 위험을 보고 경로·대상 선택 | 발견 기록, 획득 기회 | 단서가 원하는 획득과 연결 |
| 획득 | 알 조건 또는 포획·교감 조건 확인 | 보유 동료와 획득 기록 | 이 동료를 기를 이유 제시 |
| 육성 | 예상 역할·장단점을 보고 성장·기술 선택 | 개체 상태와 사용할 능력 | 다음 도전에서 선택 차이 발생 |
| 준비·도전 | 상대·환경 단서를 보고 편성·행동 선택 | 성공 또는 실패 이유 | 배운 규칙을 적용할 기회 |
| 보상·귀환 | 보상 사용처와 새 목표 확인 | 진행 기록, 사용 가능한 자원 | 다음 동료·성장·탐험에 투자 |

이 연결 중 하나가 빠지면 수집·육성·전투가 서로 따로 놀 수 있습니다. 첫 검증에서는 콘텐츠 수보다 각 결과가 다음 선택을 바꾸는지를 봅니다.

## 4 시스템별 구체화할 규칙과 대안

아래 모든 규칙 후보는 제안입니다. 공식 게임의 수치·화면·명칭을 그대로 가져오는 뜻이 아닙니다.

| 시스템 | 구체화할 입력·정보·결과 | 규칙 대안과 손익 | 첫 구간에서 확인할 질문 |
| --- | --- | --- | --- |
| 획득 | 서식 단서, 대상 선택, 성공 조건, 결과와 재시도 경로 | 알은 부화 기대감이 강하지만 보상이 늦다. 포획은 발견 순간 판단이 있지만 접근·실패 처리가 늘어난다. 구조·교감은 서사에 맞지만 반복할 이유가 필요하다. | 원하는 동료를 얻기 위해 무엇을 할지 스스로 정하는가? |
| 부화 | 남은 조건 표시, 조건을 채운 행동, 결과 확인 | 행동 완료형은 진행을 설명하기 쉽다. 재료형은 탐험 보상과 연결되지만 반복 수집 부담이 있다. 시간형은 장기 돌봄에 맞지만 기다리는 동안의 목적이 필요하다. | 단순 기다림 외에 플레이어의 선택이 있는가? |
| 육성 | 현재 특징, 성장 조건, 선택별 예상 변화, 변경 가능 여부 | 수치 상승은 이해하기 쉽지만 최적값으로 수렴하기 쉽다. 역할·기술 분기는 활용 차이가 크지만 도전도 함께 설계해야 한다. | 좋아하는 개체를 버리지 않고 원하는 역할로 기를 수 있는가? |
| 전투 | 적의 특징, 가능한 행동, 순서·비용, 승패·실패 원인 | 커맨드 턴제는 선택을 관찰하기 좋다. 자동 전투는 준비가 중요하지만 개입감이 약할 수 있다. 실시간 지시는 위치·타이밍을 살리지만 조작·카메라·연출 검증이 늘어난다. | 준비와 전투 중 판단 중 어디에 재미를 둘 것인가? |
| 탐험 | 갈 수 있는 경로, 단서, 장애물, 귀환 | 원정 선택형은 제작 범위를 관리하기 쉽다. 작은 연결 맵은 발견과 이동을 살린다. 넓은 자유 탐험은 길찾기·콘텐츠 밀도 부담이 크다. | 이동 자체에 선택이 있는가, 목적지 선택만으로 충분한가? |
| 상성·역할 | 유리한 이유, 불리한 상황, 대체 해결법 | 속성 상성은 편성을 돕지만 암기량이 늘어난다. 환경·행동 상성은 상황을 읽게 하지만 표시와 설명이 필요하다. | 한 가지 정답 생물 없이도 선택 이유가 생기는가? |
| 보상 | 획득처, 사용처, 소진 후 복구, 반복 보상 | 화폐 하나는 단순하다. 목적별 재료는 목표를 만들지만 종류가 늘수록 관리 부담이 커진다. | 보상을 어디에 쓰며 왜 다시 도전할지 알 수 있는가? |
| 보존·재개 | 획득·성장·목표·보상 상태, 저장 확인, 이어하기 위치 | 거점 저장은 상태가 단순하지만 원정 중 이탈 손실이 있다. 단계별 저장은 손실이 적지만 중복 지급·중단 상태 처리가 필요하다. | 중단·패배 후 무엇이 유지되는지 예상할 수 있는가? |

전투 참고를 커맨드 방식으로 선택한 뒤에 행동 순서·교체 비용·기술 수·속성 수·피해 공식을 정합니다. 포켓몬의 파티·기술 수나 원작의 성장 단계 수를 그대로 기본값으로 확정하지 않습니다.

## 5 A안의 첫 플레이를 끝까지 따라가는 예시

**이 절은 A안을 설명하기 위한 수동 진행용 시나리오입니다. 채택된 게임 규칙이 아닙니다.** 아래 상황 카드를 읽고 선택과 결과를 종이에 기록하는 수준이며 실제 플레이 테스트 결과는 없습니다. 플랫폼과 조작 방식에 의존하는 이동·카메라는 아직 표현하지 않습니다.

### 예시에서만 쓰는 가정

- 거점 1곳과 탐험 지역 1곳. 지역에는 둥지·회복터·관문이라는 상황 3개가 있다.
- 독자 생물의 역할 후보는 **등껍질형(안정적인 보호)**, **날개형(빠른 대응)**, **빛주머니형(서식 단서 탐색)** 3종이다. 이는 임시 역할 표기이며 최종 이름·디자인이 아니다.
- 첫 시나리오에는 등껍질형을 이미 보유하고, 날개형 알을 새로 얻는다. 빛주머니형은 다음 목표로만 제시하며 이번 획득에는 등장하지 않는다.
- 데리고 다니는 동료는 예시상 2마리, 도전에 참여하는 동료는 1마리다. 입장 전에 고르고 전투 중 교체는 생략한다.
- 첫 알은 목표 지점에서 확정 획득한다. 부화·성장에 현실 시간 대기나 유료 재화가 없고, 실패로 동료·알이 소멸하지 않는다.
- 외형은 성장 전후 2형태 이내로 가정한다. 아래 성장 선택 두 개가 별도 외형을 각각 요구하는 것은 아니다.

### 단계별 상황 카드

| 순서 | 보여줄 상황과 선택 | 기록할 결과·다음 행동 |
| --- | --- | --- |
| 1. 목표 | 거점 게시판: “산들 둥지의 알을 돌보고 관문 너머의 서식 흔적을 조사한다.” 보유 등껍질형의 보호 역할을 확인한다. | 현재 목표를 기록하고 지역으로 출발한다. |
| 2. 단서 | 갈림길 안내: 둥지에는 알, 회복터에는 따뜻한 돌이 있다. 어느 곳부터 조사할지 고른다. | 방문한 장소를 체크한다. 양쪽은 자유롭게 왕복할 수 있다. |
| 3. 알·재료 | 둥지 첫 조사에서 날개형 알 1개, 회복터 첫 조사에서 따뜻한 돌 1개를 얻는다. | 두 항목을 기록한다. 같은 첫 보상을 재지급하지 않는다. 놓쳤다면 다른 장소로 돌아간다. |
| 4. 부화 | 알 카드에 “따뜻한 돌로 보온하면 부화”라고 표시한다. 보온 행동을 고른다. | 돌 1개를 소비하고 알을 날개형 동료로 바꾼다. 획득 전과 후를 확인한다. |
| 5. 성장 | 첫 부화 임무 보상인 훈련 기회 1회를 날개형에 사용한다. 아래 ‘돌파’ 또는 ‘보호’ 역할을 고른다. | 선택 효과를 기록하고 두 상황으로 구성된 관문에 도전할 준비를 한다. |
| 6. 도전 | 관문 안내판에서 두 상황의 위험과 목표를 읽고 동료 1마리를 선택한다. | 아래 수동 규칙에 따라 결과를 진행한다. 실패하면 안내를 다시 보고 무료로 재준비한다. |
| 7. 보상 | 두 상황을 모두 해결하면 조사 표식 1개를 받는다. 거점에서 표식을 교환하면 빛주머니형의 서식 단서가 열린다고 표시한다. | 표식은 첫 성공에 1번만 지급한다. 기존 획득·성장 상태와 관문 완료를 기록한다. |
| 8. 귀환·다음 목표 | 표식 교환 후 다음 조사 목표를 확인한다. 다시 도전해 다른 역할을 비교할 수도 있다. | 다음 단서 개방과 교환 여부를 기록하고 거점에서 재개하도록 표시한다. 첫 시나리오는 여기서 끝난다. |

### 진행자가 임의로 판정하지 않기 위한 예시 도전 규칙

이것은 최종 전투 공식 대신 **역할 선택의 차이만 비교하는 상황 카드 규칙**입니다. 체력·명중·속성 배율·실시간 조작은 이 검증에 포함하지 않습니다. 전투 방식 결정 후 새로 설계할 항목입니다.

| 동료·성장 선택 | 사용 가능한 행동 | 장점과 손해 |
| --- | --- | --- |
| 날개형: 돌파 | 공격, 방어, 돌파 | 노출 상황에서 빠르게 끝내지만, 돌격 상황에서는 먼저 방어해야 한다. |
| 날개형: 보호 | 공격, 방어, 보호 | 돌격 상황을 한 행동으로 처리하지만, 노출 상황은 두 번 공격해야 한다. |
| 기존 등껍질형 | 공격, 방어, 보호 | 첫 획득·성장과 별개로 도전을 계속할 수 있는 복구 선택지다. 이번 시나리오에서는 보호 역할과 같은 규칙을 쓴다. |

1. **상황 1 — 돌격 예고:** 적이 돌진을 준비한다고 먼저 보여준다. ‘보호’를 선택하면 즉시 해결한다. ‘방어’를 선택하면 공격을 막고, 다음 행동은 ‘공격’만 선택할 수 있으며 그것으로 해결한다. 첫 행동에 ‘공격’ 또는 ‘돌파’를 고르면 해당 관문 시도가 실패한다.
2. **상황 2 — 틈이 보이는 상대:** ‘돌파’ 1번 또는 ‘공격’ 2번으로 해결한다. ‘방어’와 ‘보호’는 진행되지 않으며, 결과 안내 후 다시 고를 수 있다. 공격 횟수는 이 상황 안에서 누적되고 방어·보호로 초기화되지 않는다. 이 상황에서는 실패하지 않는다.
3. 두 상황을 순서대로 해결하면 성공한다. 돌파형은 두 상황을 2행동+1행동, 보호형은 1행동+2행동으로 해결하므로 이 예시에서는 총행동 수가 같다. 어느 역할을 선택해도 완료할 수 있다.
4. 실패하면 관문 입구로 돌아가 상황 1부터 다시 시작한다. 획득한 동료·성장 선택은 유지하고 추가 재료는 요구하지 않는다. 예시에서는 관문 입구에서 성장 역할도 무료로 바꿀 수 있다. 승패 뒤 동료를 회복한 것으로 처리한다.
5. 성공 후 재도전은 역할 비교용이며 조사 표식을 다시 지급하지 않는다. 재도전 실패는 이미 완료한 관문과 지급받은 보상을 취소하지 않는다.

이 카드 예시는 선택에 따라 **행동 순서가 달라진다는 연결**만 보여줍니다. 성장의 장기 가치, 전투의 깊이, 난이도, 상성 균형, 애착이 검증되었다고 해석하지 않습니다. 기존 등껍질형도 관문을 통과할 수 있게 한 이유는 특정 새 동료가 없으면 진행이 막히는 구조를 피하는 선택지를 비교하기 위해서입니다.

### 중단·실패·반복 획득에 대한 예시 기록 규칙

종이 진행에서는 결과가 확정될 때마다 다음 내용을 체크합니다. 실제 저장 시스템은 구현하지 않았습니다.

- 둥지·회복터의 첫 보상 수령 여부, 알 또는 동료의 현재 상태, 훈련 기회 수령·사용 여부.
- 보유 동료와 성장 역할, 관문 완료, 조사 표식 지급·소비 여부, 다음 단서 개방.
- 부화는 ‘돌 소비 + 알 제거 + 동료 추가’를 한 결과로, 교환은 ‘표식 소비 + 단서 개방’을 한 결과로 기록한다. 중간 상태에서 두 보상을 모두 받는 처리를 허용하지 않는다.
- 도전 도중 중단했다면 관문 입구에서 다시 시작한다. 앞서 확정한 획득·성장은 유지한다. 중복 지급 방지 규칙은 이어하기 후에도 동일하다.
- 단계별 확인 메시지 예시: “날개형이 동료가 되었습니다”, “보호 역할을 선택했습니다”, “다음 조사 단서가 열렸습니다”. 실제 UI 문구는 추후 조정한다.

## 6 B안을 먼저 고르면 달라지는 첫 플레이

아래 역시 선택지 비교를 위한 예시이며 실시간 포획을 확정하지 않습니다. 동일한 작은 지역에서 **단서 관찰 → 접근 선택 → 획득 → 성장 → 도전**을 시험할 수 있습니다.

| 항목 | A안 예시 | B안으로 바꿀 경우의 후보 |
| --- | --- | --- |
| 첫 발견 | 둥지의 알 | 흔적을 따라 발견한 야생 개체 |
| 획득 선택 | 부화 조건 채우기 | 관찰로 얻은 정보에 따라 먹이 유인·조용한 접근·전투 후 확보 등을 비교하고 하나를 주력으로 선택 |
| 실패 | 조건이 부족하면 다른 장소 방문 | 경계 상승이나 도주를 보여주고 안전 지점에서 재시도. 재등장 조건과 소모품 복구 경로를 정해야 함 |
| 성장 연결 | 부화 후 역할 선택 | 확보한 개체를 동료로 삼은 이유와 성장 역할 연결 |
| 추가로 필요한 자료 | 알·부화 상태와 조건 표시 | 발견·경계·접근·성공·도주 상태, 단서 신뢰도, 입력 방식 |

포획 성공률 공식이나 실제 입력 타이밍은 아직 제안하지 않았습니다. 포켓몬에서 원하는 것이 야생 탐색인지 전투 중 확보인지부터 답을 받은 뒤, A안과 같은 수준의 상황 카드로 상세화합니다. A·B를 동시에 완전 구현하는 것은 첫 범위의 전제가 아닙니다.

## 7 화면 흐름과 기획 데이터의 최소 목록

화면을 몇 장으로 분리할지는 플랫폼 선택 뒤 정합니다. 지금은 플레이어가 알아야 하는 정보와 상태를 대응시킵니다.

| 흐름 | 꼭 보여줄 정보 | 다음 행동 |
| --- | --- | --- |
| 거점·목표 | 보유 동료, 선택한 목표, 보상 사용처 | 출발, 육성, 교환 |
| 탐험 | 현재 위치 또는 상황, 발견 단서, 가능 경로 | 조사, 획득, 귀환 |
| 동료·성장 | 현재 역할, 조건, 선택 전후 변화 | 성장 선택, 편성, 돌아가기 |
| 도전 준비 | 상대·환경 힌트, 참여 동료, 실패 비용 | 시작, 준비 변경 |
| 도전·결과 | 가능한 행동, 행동 결과, 성공·실패 이유 | 다음 상황, 재시도, 귀환 |
| 재개 | 유지된 동료·성장·보상과 현재 목표 | 이어하기 |

기획자가 채울 자료는 다음과 같습니다. 엔진 파일이나 코드 구조를 정하는 목록이 아닙니다.

- **생물 카드:** 독자적인 외형 모티프, 서식 단서, 획득 방법, 기본 역할, 성장 선택별 장단점, 도전에서의 사용 사례.
- **개체 기록:** 별명, 획득 장소·계기, 현재 성장, 선택한 역할·기술. 종의 공통 정보와 개체별 기록을 구분한다.
- **지역 카드:** 출입 조건, 연결 장소, 보여줄 단서, 획득 후보, 장애물, 필수 동료가 없을 때의 대안.
- **도전 카드:** 입장 정보, 행동·결과 규칙, 해결 조건, 실패 원인·복구, 첫 보상과 반복 보상.
- **보상·진행 기록:** 얻는 곳, 쓰는 곳, 소진·중단 처리, 한 번만 지급하는지, 다음 목표와의 연결.

## 8 먼저 결정할 선택과 결정 후 달라질 문서

| 순서 | 선택 | 결정이 바꾸는 부분 |
| --- | --- | --- |
| 1 | 포켓몬에서 원하는 재미: 포획·모험 / 상성·커맨드 배틀 / 둘 다 | A·B 중 먼저 상세 검증할 방향, 획득·탐험과 전투의 비중 |
| 2 | 플랫폼·표현, 인원·가능 시간·마감 | 화면·조작, 자산 수, 작은 검증 구간의 실제 제작 범위 |
| 3 | 주력 획득: 알 / 포획 / 구조·교감 | 부화 조건 또는 접근·실패 규칙, 보상 속도 |
| 4 | 전투·도전: 커맨드 / 준비 후 자동 / 실시간 / 탐험 문제 중심 | 입력·행동 순서·피드백, 필요한 기술·애니메이션 |
| 5 | 육성: 수치 / 역할·기술 / 성장 분기, 선택 변경 가능 여부 | 개체 차이와 재육성, 도전별 역할 설계 |

선택 결과는 [기획 결정 체크리스트](02_기획_결정_체크리스트.md)에 날짜·이유와 함께 남깁니다. 한 선택이 바뀌면 관련 부분을 갱신하고, 예시 규칙을 자동으로 확정 규칙으로 승격하지 않습니다. 작업 순서와 범위 축소 기준은 [검증 범위와 의존성](04_검증_범위와_의존성.md)을 따릅니다.
