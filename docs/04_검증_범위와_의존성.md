# PokemonGame 검증 범위와 의존성

기준일: 2026년 11월 4일. [기획 결정 체크리스트](02_기획_결정_체크리스트.md)의 질문을 실제로 확인할 작업 순서로 바꾼 문서입니다.

**확인된 방향:** 사용자가 참고하려는 작품은 컬렉션이 아닌 **옛 원작 드래곤빌리지**입니다. 옛 원작에서 기억하는 정확한 시기와 좋아했던 행동은 추가로 구체화할 수 있습니다.
**미정:** 포켓몬 참고 작품, 플랫폼, 제작 인원·마감, 표현 방식, 획득·성장·전투 규칙은 아직 확정하지 않았습니다.
**문서의 지위:** 아래는 단계별 검증 제안입니다. 최종 MVP, 개발 일정, 확정된 기능 명세가 아닙니다. 현재 산출물은 기획 초안과 검증 기록 양식이며, 실제 검증은 아직 하지 않았습니다. 코드 구현은 포함하지 않습니다.

## 1 먼저 확인할 가설

> 내가 찾아 얻고 성장 방향을 고른 동료가 다음 도전을 다르게 해결하게 만들면, 플레이어는 그 동료를 계속 키우고 다시 탐험하고 싶어진다.

이 문장은 새 게임을 위한 **가설**이며 두 원작의 공식 설명이나 검증된 결과가 아닙니다.

| 확인할 연결 | 관찰하려는 행동 | 연결이 약하다는 신호 |
| --- | --- | --- |
| 탐험 → 획득 | 단서를 보고 원하는 획득 목표를 선택함 | 이유 없이 같은 버튼만 반복함 |
| 획득 → 애착 | 새 동료의 특징을 보고 키울 이유를 말함 | 수치가 낮다는 이유만으로 즉시 버림 |
| 성장 → 도전 | 성장 선택에 따라 준비나 행동을 바꿈 | 어떤 선택을 해도 같은 방법으로 해결함 |
| 도전 → 재탐험 | 보상을 보고 다음 목표를 세움 | 보상은 받지만 사용할 곳을 모름 |

## 2 단계별 검증 범위

| 단계 | 확인할 질문 | 만들 자료 | 다음 단계로 넘어갈 근거 |
| --- | --- | --- | --- |
| 방향 정리 | 옛 드래곤빌리지와 포켓몬에서 각각 무엇을 살릴까? | 좋아했던 행동, 핵심 가설, 확정·미정 표 | 핵심 재미와 비교할 선택지를 구분해 설명할 수 있음 |
| 문서·카드 검증 | 획득·성장·도전이 하나의 흐름으로 이어질까? | 흐름도, 동료 카드, 상황 카드, 보상 기록지 | 진행자가 임의로 규칙을 덧붙이지 않아도 끝까지 진행 가능 |
| 화면 흐름 검증 | 무엇을 보고 어떤 선택을 해야 하는지 알까? | 종이 화면 또는 정적인 화면 초안 | 다음 행동·선택 결과·재시도 경로를 찾는 과정을 관찰 가능 |
| 작은 플레이 구간 | 정한 조작과 규칙으로도 같은 재미가 생길까? | 향후 구현 대상 구간의 명세 | 플랫폼·제작 조건·핵심 규칙이 정해지고 구현 작업이 별도로 요청된 뒤 진행 |
| 확장 판단 | 더 많은 종류·지역이 재미를 늘릴까? | 검증 결과와 추가 콘텐츠의 목적 | 해결되지 않은 핵심 문제와 단순 콘텐츠 부족을 구별 가능 |

막힌 단계에서는 종류나 맵을 늘리기보다 원인이 된 연결을 다시 설계합니다. 문서상 통과는 실제 조작감이나 플레이 재미의 검증을 대신하지 않습니다.

## 3 작은 플레이 구간의 예시 제안

**아래 수량은 범위를 이해하기 위한 가정입니다. 채택 결정, 제작량 약속, 소요 시간 추정이 아닙니다.** 전투를 낮은 비중으로 정한다면 도전은 탐험 문제나 조사 임무로 바꿀 수 있습니다.

| 요소 | 예시 가정 | 검증에서 맡을 역할 |
| --- | --- | --- |
| 공간 | 거점 1곳 + 탐험 지역 1곳 | 출발·선택·귀환의 맥락 제공 |
| 동료 | 역할이 다른 독자 생물 3종, 성장 전후 2형태 이내 | 선택에 따라 다른 해결법이 있는지 비교 |
| 획득 | 주력 방식 1개 | 알·포획·교감 중 선택한 방식의 재미 확인 |
| 성장 | 결과를 예측할 수 있는 선택 1번 | 같은 개체를 다르게 활용하는 경험 확인 |
| 도전 | 규칙을 익히는 상황 1개 + 응용 상황 1개 | 배운 규칙을 스스로 활용하는지 확인 |
| 보상 | 다음 획득 또는 성장에 쓰는 보상 | 반복할 이유와 보상 사용처 확인 |
| 재개 | 저장 지점과 이어하기 상태를 보여주는 흐름 | 획득한 동료와 성장이 유지된다는 기대 확인 |

제안 흐름: **목표 확인 → 탐험 선택 → 동료 획득 → 성장 선택 → 준비 → 도전 → 결과 확인 → 다음 목표 선택**.
획득에서 알을 선택하면 부화 조건을, 포획을 선택하면 접근·성공·실패 조건을 정의합니다. 두 방식을 모두 넣는 것은 전제하지 않습니다.
전투 방식과 파티 규모를 정하기 전에는 기술 수·속성 수·피해 공식·조작 키를 확정하지 않습니다.
애니메이션과 완성 그림 대신 독자적인 임시 도형·역할 카드로 선택의 차이를 먼저 표현할 수 있습니다.

## 4 결정과 작업의 의존성

| 선행 결정·자료 | 이어지는 작업 | 선행 내용이 없을 때 가능한 일 |
| --- | --- | --- |
| 살릴 재미와 참고 장면 | 핵심 가설·획득 방식 비교 | 옛 원작의 기억과 현재 공식 자료가 다른 지점을 기록 |
| 플랫폼·인원·마감·표현 수준 | 조작·화면·자산 규모와 구현 범위 | 플랫폼에 의존하지 않는 카드 흐름 작성 |
| 주력 획득 방식 | 탐험 단서·성공·실패·부화 조건 | 알·포획 등의 대안을 짧은 흐름으로 비교 |
| 성장의 의미 | 동료 역할·성장 결과·선택 변경 가능성 | 수치 성장과 역할 변화의 장단점 정리 |
| 전투 또는 도전 방식 | 행동·순서·비용·승패·실패 후 복구 | 해결할 상황과 선택 이유를 먼저 작성 |
| 획득·성장·도전 연결 | 보상·재화의 획득처와 사용처 | 필요한 보상 목적을 나열하고 중복 제거 |
| 전체 흐름과 보존할 상태 | 저장·재개 시점과 화면 목록 | 무엇이 사라지면 안 되는지 사용자 관점으로 기록 |
| 문서 검증 결과와 제작 조건 | 향후 구현할 작은 구간 확정 | 바꿀 규칙과 보류할 기능을 정리 |

순서는 **핵심 재미 → 획득·성장·도전의 연결 → 보상·재개 → 화면·자산 → 구현 범위**를 제안합니다. 플랫폼·인원·마감은 화면·자산 계획에 앞서 함께 정리합니다.

## 5 실행할 기획 작업과 완료 기준

[게임 구조와 첫 플레이](03_게임_구조와_첫_플레이.md)에 결합안·순환·상황 카드·성장·실패·보상·재개 규칙의 **초안**을 작성했습니다. 아래 체크는 초안 존재 여부가 아니라 오른쪽 기준까지 확인했는지를 뜻합니다. 사용자 선택과 수동·관찰 검증은 아직 진행하지 않았습니다.

| 완료 | 작업 | 결과물과 완료 기준 |
| --- | --- | --- |
| [ ] | 좋아했던 경험을 구체화 | 사용자 기억에서 재미있던 행동·기대·불편을 구분하고, 사실 확인이 필요한 기억은 따로 표시 |
| [ ] | 획득 후보 비교 | 각 후보의 시작 조건·선택·성공·실패·재시도를 적고 주력 방식 선택에 필요한 차이를 설명 |
| [ ] | 한 사이클 작성 | 모든 단계에 플레이어 입력, 보이는 정보, 결과, 다음 이동 경로가 있음 |
| [ ] | 성장 선택 작성 | 선택 전 예상 결과를 설명하고, 다음 도전에서 달라지는 행동을 대응시킴 |
| [ ] | 도전과 실패 경로 작성 | 승패 또는 해결 조건과 실패 후 바꿔볼 준비·행동을 명시 |
| [ ] | 보상 사용처 연결 | 보상마다 쓰는 곳과 다시 얻는 경로가 있고, 소진으로 진행이 막히는 경우의 복구 경로가 있음 |
| [ ] | 수동 진행 | 진행자가 규칙을 임의로 보완한 지점을 기록하고 명세의 빈칸을 수정 |
| [ ] | 관찰 진행 | 도움 없이 한 행동과 설명을 받은 뒤 한 행동을 구분해 기록 |
| [ ] | 재개 상태 정리 | 동료·성장 선택·획득 보상·진행 목표 중 유지할 항목과 저장 시점을 대응시킴 |
| [ ] | 범위 재검토 | 포함할 항목마다 검증 가설을 연결하고, 관계없는 기능은 보류 목록으로 이동 |

## 6 위험과 줄이는 순서

| 위험 신호 | 먼저 바꿀 것 | 확인할 결과 |
| --- | --- | --- |
| 성장 선택이 결국 같은 최강 수치로 수렴 | 도전에 필요한 역할과 선택의 손익을 다시 설계 | 다른 선택을 할 이유를 설명할 수 있음 |
| 좋은 개체만 남기느라 애착이 사라짐 | 무작위 차이의 크기·보정·재육성 가능성 비교 | 좋아하는 개체를 계속 기를 경로가 있음 |
| 부화나 재료 수집이 기다림뿐임 | 행동으로 진행되는 조건과 기다리는 동안의 목표 비교 | 반복 행동에 판단이나 발견이 있음 |
| 기능은 많지만 흐름을 이해하지 못함 | 주력 획득 방식과 핵심 성장 선택에 설명을 집중 | 다음 목표를 스스로 찾음 |
| 생물·성장형·방향별 표현이 급증 | 필요한 상태를 셈하고 임시 표현·공유 가능한 연출 검토 | 테스트에 필요한 표현과 완성용 표현이 구분됨 |
| 실패가 무엇 때문인지 알 수 없음 | 정보 표시와 결과 피드백, 재시도 비용을 조정 | 다음 시도에서 바꿀 행동을 제안함 |

**줄이는 순서 제안:** 온라인 거래·대전·수익화 → 부가 꾸미기·교배·중복 성장 체계 → 추가 지역·생물·분기 → 완성 연출·복잡한 확률 → 핵심 규칙 단순화.
핵심 가설에 직접 필요한 요소라면 이 순서를 바꿉니다. 줄일 때도 **획득 결과의 이해, 성장의 의미, 실패 후 복구, 다음 목표**는 검증 가능하게 남깁니다.
시간이 부족하다는 이유로 획득만 만들고 성장·도전을 생략하면 이번 가설을 검증할 수 없으므로, 표현 수준을 낮춰도 전체 순환을 남기는 쪽을 먼저 검토합니다.

## 7 관찰 기록지

참가자 수·세션 길이·목표 수치는 아직 정하지 않았습니다. 테스트 목적과 제작 조건을 정한 뒤 설정하며, 아래 기록만으로 검증 통과를 선언하지 않습니다.

| 기록 항목 | 작성란 |
| --- | --- |
| 검증 날짜·자료 버전·진행자 | 미정 |
| 확인할 가설과 바꾼 규칙 | 미정 |
| 참가자의 관련 게임 경험 | 개인 식별 정보 없이 필요한 수준으로 기록 |
| 시작할 때 제공한 안내 | 실제로 보여준 문장과 화면 기록 |
| 참가자가 본 정보와 실제 선택 | 해석을 덧붙이기 전에 관찰 행동 기록 |
| 막힌 위치·진행자의 도움 | 도움 전후를 구분하고 설명한 내용을 기록 |
| 참가자가 예상한 결과와 실제 결과 | 차이와 그 이유에 대한 참가자의 설명 기록 |
| 성장 후 달라진 준비·행동 | 관찰됨 / 관찰되지 않음 / 확인하지 못함 및 근거 |
| 실패 후 바꾸려 한 행동 | 선택과 그 이유 기록 |
| 마무리 후 스스로 정한 다음 목표 | 목표를 말했는지와 실제 선택을 구분 |
| 유지·수정·보류할 규칙 | 근거가 된 행동과 함께 기록 |
| 다음 검증에서 확인할 질문 | 아직 답하지 못한 질문을 구체적으로 기록 |

질문 예시: “방금 왜 그 동료를 골랐나요?”, “성장 후 무엇이 달라졌나요?”, “다시 한다면 무엇을 바꾸겠나요?”, “이 보상으로 다음에 무엇을 하고 싶나요?”
좋다는 평가와 실제 행동이 다르면 둘 다 기록합니다. 진행자의 설명으로 해결된 문제는 독립적으로 이해한 결과로 세지 않습니다.

## 8 단계 종료 기록

- 유지할 가설과 그 근거: 미정.
- 바꿀 규칙과 기대하는 변화: 미정.
- 먼저 정해야 하는 사용자 선택: 미정.
- 다음 검증에 포함할 것 / 보류할 것 / 보류 이유: 미정.
- 구현에 앞서 필요한 제작 조건과 명세: 미정.

핵심 연결이 약하면 같은 범위에서 다시 확인합니다. 연결이 이해되고 선택 차이가 관찰되면 그 결과를 바탕으로 다음 범위를 제안하며, 최종 게임의 기능 수로 곧바로 확대하지 않습니다.
